#### 2. Cylindrical

4. **Manual linear algebra**: Rust implements Cramer's rule for 3×3 systems instead of using Eigen. More code, same result.

**Hacks/Workarounds**:
- C++: 0 — clean and simple
- Rust: 1 — the manual 3×3 solve with centering for numerical conditioning is verbose but not hacky; LM with numerical Jacobian is a minor concern.

**Numerical Robustness**: Rust wins due to LM refinement. The C++ Kasa fit without refinement can produce biased results for short arcs.

**Recommendation**: **Keep Rust**. The LM refinement is worth it. Consider eventually switching to an analytic Jacobian for speed.

#### 4. Conical

**C++ (ConicalTraits, via unified cone/cylinder)**:
- Fit (`fit_cone` in surface_fit.cpp): Multi-step:
  1. Center face normals, SVD of Nc^T Nc → axis (smallest eigenvector)
  2. `n_mean · axis` → initial half-angle
  3. Face-normal-ray LS → axis lateral position
  4. Vertex r/h → apex height (try both signs, pick lower variance)
  5. **6-param Gauss-Newton refinement** with analytic Jacobian (α, h_apex, q_u, q_w, δ_u, δ_w) when nv ≥ 10
- The Jacobian is computed analytically (lines 200-220 of surface_fit.cpp)
- Seed: 3-face (shared with cylinder)
- Unified: if cylinder fits better, uses cylinder

**Rust (ConicalSurface)**:
- Fit (`fit_cone` in conical.rs): Multi-step:
  1. `compute_cone_axis()` — 3 strategies: (a) covariance eigenvector (≥8 faces), (b) apex-vertex→base-centroid direction, (c) cross product of normal differences
  2. `fit_cone_profile()` — linear regression of r vs h, or fallback to face-normal-based half-angle estimation
  3. Axis orientation correction
  4. **6-param LM refinement** with numerical Jacobian when nv ≥ 10
  5. Multi-axis rescue: if initial fit fails vertex tolerance, tries LM from 6 different axis guesses including coordinate axes
- Seed: **apex-vertex seeding** (very different from C++) — collects all faces incident on a vertex that has many non-coplanar incident faces
- Runs after cylinders (separate pass)

**Key Differences**:
1. **Seeding**: Fundamentally different. C++ uses 3-face neighbor seeds (same as cylinder). Rust uses apex-vertex seeding — finds vertices shared by many faces with non-coplanar normals (likely cone tips). The Rust seed strategy is much better for cone tip geometry but means it must iterate over all face-vertex incidences (O(F²) worst case without precomputed vertex-to-face map).
2. **Axis estimation**: C++ uses centered-normal SVD only. Rust has 3 fallback strategies for small face counts — more robust for sparse seeds.
3. **GN/LM refinement**: Both have it. C++ uses analytic Jacobian (faster, more accurate). Rust uses numerical Jacobian via finite differences.
4. **Multi-axis rescue**: Rust has a fallback that tries 6 axis candidates when the initial fit fails. C++ does not. This is a significant robustness advantage.
5. **Unified vs separate**: C++ tries both cylinder and cone. Rust skips faces already assigned to cylinders.

**Hacks/Workarounds**:
- C++: 1 — the "try both signs for apex height and pick lower variance" is a workaround for cone orientation ambiguity
- Rust: 3 — the 3-strategy `compute_cone_axis()` fallback chain, the apex-vertex seeding brute-force face scan, and the multi-axis rescue that tries coordinate axes as cone axis candidates

**Numerical Robustness**: **Rust wins** overall due to multi-axis rescue and more fallback strategies. C++ has better Jacobian accuracy (analytic).

**Recommendation**: **Keep Rust's approach**, but port the analytic Jacobian from C++ to replace the numerical one. The apex-vertex seeding is genuinely better for cone geometry. The multi-axis rescue catches cases the C++ misses.

#### 5. Toroidal

**C++ (ToroidalTraits)**:
- Fit (`fit_torus` in surface_fit.cpp): 
  1. **PCA of vertex positions** → axis (smallest positional variance direction). Comment explains this works because axis variance ~ r²/2 while perpendicular ~ (R²+r²/2)/2.
  2. Kasa 2D circle fit in perpendicular plane → center lateral position
  3. Linearized (radial, axial) circle fit → R, r
  4. **7-param Gauss-Newton** with analytic Jacobian (cx, cy, cz, R, r, δ_u, δ_w) — 30 iterations
- Seed: 1-ring vertex neighborhood (same as sphere)
- Acceptance: angular coverage around minor circle (tube cross-section), which is distinct from the cylindrical angular coverage

**Rust (ToroidalSurface)**:
- Fit (`fit_torus` tries two methods, picks better):
  - **Method 1** (`fit_torus_inner`): Medial axis / tube center method:
    1. Estimate minor radius from normal-line intersections of adjacent face pairs
    2. Compute tube centers k_i = p_i ± r*n_i
    3. PCA + 2D circle fit of tube centers → center, axis, R
    4. **7-param LM refinement** with numerical Jacobian
  - **Method 2** (`fit_torus_sor`): Surface-of-revolution approach:
    1. Normal covariance smallest eigenvector → axis
    2. Linear regression of s = r² + h² vs r → R, r
    3. **7-param LM refinement** with numerical Jacobian
  - Picks whichever gives lower max vertex error
- Seed: 1-ring (same) 
- Acceptance: angular coverage (same gap-based check as cylindrical)

**Key Differences**:
1. **Axis estimation**: C++ uses vertex-position PCA (smart insight — well-commented). Rust method 1 uses tube-center PCA (requires accurate minor radius first), method 2 uses normal-covariance (same as cylinder).
2. **Initial radius estimation**: C++ uses a clean linearized circle fit in (radial, axial) space. Rust method 1 uses normal-line intersections with 25th-percentile robust estimation — more complex, more heuristic, more code. Rust method 2 uses linear regression of s vs r — similar spirit to C++.
3. **Refinement**: Both have it. C++ uses analytic Jacobian. Rust uses numerical Jacobian.
4. **Dual method**: Rust tries two methods and picks the better one — a robustness advantage.
5. **Quality gates**: Rust has explicit RMS gate on tube-center circle fit quality (reject if tube centers don't form a good circle). C++ relies on vertex tolerance.

**Hacks/Workarounds**:
- C++: 1 — the position PCA comment acknowledges it doesn't work for self-intersecting tori (R < r), rejected with `if (r > R) return false`
- Rust: 3 — the normal-line intersection with 25th-percentile, the sign-search (try both tube center signs), and the dual-method fallback

**Numerical Robustness**: **Roughly tied**. The C++ approach is cleaner and has analytic Jacobians. The Rust dual-method approach handles more edge cases. Both should work well on well-behaved tori.

**Recommendation**: **Port the C++ vertex-position-PCA axis estimation to Rust** as a third fallback in `fit_torus`. The C++ insight about axis from positional variance is elegant and may be more reliable than normal-line intersections. Keep the Rust dual-method approach. Replace the numerical Jacobian with the C++ analytic one.
